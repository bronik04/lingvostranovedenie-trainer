# Правила работы

- Вопрос всегда по-русски, варианты всегда по-китайски. Проверяется `scripts/normalize.py`,
  нарушение останавливает сборку.
- Формулировки не сокращать. Если источники расходятся по длине, берётся полная редакция.
- Ответы не выдумывать: нет подтверждающего источника — `needs-review`, расхождение с
  официальным ключом — `conflict` и запись в отчёт волны.
- `sources/` не редактировать: это неизменяемые первоисточники.
- `data/bank.json` правится только скриптами, руками — никогда.
- Исправить формулировку (русскую `questionRu` или китайскую `questionZh`), вариант,
  пояснение или тему готового вопроса — только через `data/review/editorial.json`
  (ключ — итоговый id, обязательна `reason`). Это касается и дополнений `addition-*`:
  правки накладываются последним слоем, после них.
  Не править текст на входе слияния: id олимпиадного вопроса вычисляется из текста,
  и у учеников пропал бы прогресс.
- Подписи к неверным вариантам — только в `data/review/glosses.json` (у вопросов досье — в ячейках таблицы досье) и только принятые
  автором: одна строка по-русски, источник, копия текста варианта. Изменился вариант —
  сборка остановится, подпись нужно перепроверить.
- Досье — таблица проверенных фактов (`data/dossiers/<id>.json`) и вопросы по её ячейкам
  (`data/dossiers/<id>-questions.json`), спецификация —
  `docs/superpowers/specs/2026-10-14-dossier-money-pilot-design.md`. Варианты вопроса досье не
  пишутся руками: правильный — ячейка, неверные — та же колонка соседних строк (общий набор),
  подписи — из ячеек таблицы, а не из `glosses.json`. У строки — не меньше двух официальных или
  академических источников с цитатой. В банк идут только вопросы со `status: "accepted"`,
  принятые автором после проверки отдельным агентом. id вопроса (`<id досье>-qNN`) и id
  варианта (id строки) не менять: на них держится прогресс учеников. Проверка без сборки:
  `python3 scripts/dossiers.py`.
  Олимпиадный вопрос можно встроить в досье: вопрос досье с полем `embeds` (итоговый id записи)
  не создаёт новую запись, а добавляет олимпиадной общий набор из колонки таблицы и подписи из
  ячеек (`scripts/embeds.py`, слой после `retired.json`); id, формулировка и исходные варианты
  записи не меняются, у принятой — не может быть подписей в `glosses.json` (черновик их не трогает: банк живёт с ними, пока вопрос не принят), пояснение не называет
  неверных вариантов. Ячейка может ссылаться на строку другого досье: `ref` — тот же персонаж
  (текст совпадает с ячейкой `name`), `from` — назван по; утечки ищутся по всем досье сразу.
  В каждом досье — примерно 70 % вопросов о Китае и 30 % о России (решение автора 2026-10-15);
  колонка `country` разводит китайские и российские варианты.
- Склеить дубли (тот же вопрос, те же варианты и ответ, разная формулировка) — только через
  `data/review/merges.json` (ключ — id оставшейся записи, `absorbs`, `reason`). Записи с
  тем же вопросом и тем же ответом, но другими неверными вариантами склеиваются только с
  пометкой `"distractors": "pool"`: варианты складываются в общий набор, раунд каждый раз
  показывает правильный и три случайных; пояснение такой записи не называет неверных
  вариантов (о них — подписи). Правки идут до склейки, поэтому вариант из общего набора
  правится в `editorial.json` у влитой записи по её собственному id варианта, а подпись к
  нему пишется к итоговой записи по `o5`, `o6`…; если поменять `absorbs`, эти id
  перенумеруются (сборка остановится на копии `zh` в подписи). Записи с разными ответами
  на один вопрос склеивать нельзя — их связывает `data/review/fact-groups.json`, а если автор
  решил оставить одну из них — `data/review/retired.json` (ключ — id удаляемой записи,
  `keptIn`, `reason`): запись уходит из банка, её id переезжает в `mergedIds` оставшейся. Влитые
  id остаются в `mergedIds`: на них
  держится перенос прогресса учеников, так что не удалять запись из банка без склейки.
  Правки и проверки влитых записей из `editorial.json`, `verification.json` не удалять:
  склейка сравнивает варианты уже после правок (без исправленной опечатки в варианте
  пара не совпадёт, и сборка остановится).
- Раздел «Чэнъюй» живёт отдельно от банка (`data/chengyu/`, `scripts/chengyu.py`): правило
  «вопрос по-русски, варианты по-китайски» к нему не относится. Олимпиадные задания — дословно
  из бланков `sources/chengyu/`, ключ подтверждается `python3 scripts/chengyu.py --sources`;
  id задания `cy-<чэнъюй>` не менять (на нём прогресс). Составленные задания — только черновики
  `drafts.json`, в раздел идут со `status: "accepted"` после проверки агентом и решения автора.
- Тесты: `python3 -m unittest discover -s test -t .` и `node --test test/*.test.mjs`.
  Браузерный `test/ui.test.mjs` проходит собранный `dist/` в Chrome без окна; ему нужны
  установленный Google Chrome и `npm ci`. Локально без них он пропускается, в CI падает.
- В Python 3.14 стандартный пакет `test` перехватывает импорт, поэтому в `test/` лежит
  `__init__.py`, а discover запускается с `-t .`.
- Паттерн `test/*.test.mjs` — без кавычек: пусть его раскрывает shell, а не встроенный
  глоб `node --test` (в Node 20, который используется в CI, такого глоба ещё нет).
- Каждое заметное изменение (фича, починка, дизайн-решение) — короткая запись в
  `CHANGELOG.md` рядом с коммитом. Это единственный источник правды о том, что
  реально сделано; не полагаться на память из предыдущих сессий или чужие отчёты.
