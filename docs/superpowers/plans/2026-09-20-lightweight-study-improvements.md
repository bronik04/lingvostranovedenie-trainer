# Lightweight Study Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve database search, repeat each mistaken question once during a round, and restore the learner's round settings after reload without adding a backend or dependencies.

**Architecture:** Keep pure record and settings transformations in `src/quiz.mjs`, where Node tests can exercise them without a browser. Keep the queue, `localStorage` I/O, and DOM rendering in `src/quiz.ui.js`; the existing bank and progress formats stay compatible.

**Tech Stack:** Vanilla browser JavaScript, localStorage, static HTML/CSS, Node's built-in test runner, Python build script.

**Spec:** `docs/superpowers/specs/2026-09-20-lightweight-study-improvements-design.md`

## Global Constraints

- The project remains a single generated HTML file with no server, dependency, or network storage.
- Question wording stays in Russian and answer options stay in Chinese.
- `data/bank.json` is generated by scripts and must not be edited by hand.
- Progress export/import keeps its existing version and payload format.
- Preserve existing uncommitted work; stage only hunks belonging to this feature if a commit is made.

## Review Focus

- An empty search query must return every card, while a Chinese answer and an explanation fragment must each find their owning record. Covered in Task 1.
- A retry must wait for exactly three later cards when the original round has enough cards. Covered in Task 3.
- Errors in the final three positions must still return once before the result screen. Covered in Task 3.
- A retry answered incorrectly must not create another retry or make a round unfinishable. Covered in Task 3.
- Damaged or stale saved settings must fall back safely and must not select values absent from the current bank. Covered in Task 1.

### Task 3: Return mistaken questions once during a round

**Files:**
- Modify: `src/quiz.mjs`
- Modify: `src/quiz.ui.js`
- Modify: `test/quiz.test.mjs`
- Modify: `CHANGELOG.md`

**Interfaces:**
- Produces `nextRetryInsertion(queue, position, roundLength): number`, returning the queue index to insert or `-1` when no retry is due.
- Produces `queueRetry(queue, retriedIds, record, position): { queue, retriedIds }`, which adds a record only once with `afterPosition: position + 4`.
- `queue` entries have `{ record, afterPosition }`; `position` is the index about to render; `roundLength` is the current dynamic round length.
- `state.retryQueue` holds pending entries and `state.retriedIds` prevents adding the same record more than once per round.

- [ ] **Step 1: Write failing unit tests for normal and end-of-round insertion**

  Add tests in `test/quiz.test.mjs`:

  ```js
  test('ошибка возвращается после трёх следующих вопросов', () => {
    const queue = [{ record: record('a'), afterPosition: 4 }];
    assert.equal(nextRetryInsertion(queue, 3, 10), -1);
    assert.equal(nextRetryInsertion(queue, 4, 10), 0);
  });

  test('ошибка в конце раунда возвращается до итогов', () => {
    const queue = [{ record: record('a'), afterPosition: 8 }];
    assert.equal(nextRetryInsertion(queue, 5, 5), 0);
  });

  test('повтор не добавляется второй раз', () => {
    const first = queueRetry([], new Set(), record('a'), 0);
    const second = queueRetry(first.queue, first.retriedIds, record('a'), 5);
    assert.equal(second.queue.length, 1);
    assert.equal(second.queue[0].afterPosition, 4);
  });
  ```

- [ ] **Step 2: Run the focused tests and confirm they fail**

  Run: `node --test test/quiz.test.mjs`

  Expected: failure because `nextRetryInsertion` is not exported.

- [ ] **Step 3: Implement queue selection and UI integration**

  Add `queueRetry()` in `src/quiz.mjs`: return unchanged values when `retriedIds` already contains the record ID; otherwise return a new queue with `{ record, afterPosition: position + 4 }` and a new set containing its ID. Add `nextRetryInsertion()`: select the first entry with `afterPosition <= position`; if none is due but `position >= roundLength`, select the first pending entry; otherwise return `-1`.

  In `startRoundWith()`, reset `retryQueue` and `retriedIds`. On an incorrect answer, assign the return of `queueRetry()` to these two state fields. In `nextQuestion()`, increment the position, use `nextRetryInsertion()` to remove one queued entry and splice its record at the current position before deciding whether the round is finished. This makes the retry appear after three later cards, or before results when the source round ends.
