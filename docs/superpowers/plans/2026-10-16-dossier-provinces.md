# Досье «Провинции и города»: план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** досье «Провинции и города» (`data/dossiers/provinces.json`) с проверенными таблицами
`provinces` и `cities`, около 45 новыми вопросами и встраиванием до 41 олимпиадного вопроса. Итог —
приёмка автором и слияние в master.

**Architecture:** новый код не нужен: система досье готова. Работа — пустое досье в сборке (одна
правка теста), общий набор инструментов сборщиков в рабочей папке и пять содержательных этапов с
агентами: сборщики → сверщики → писатели → проверяющие → автор.

**Tech Stack:** Python 3 (`scripts/dossiers.py`, `scripts/embeds.py`, `scripts/merge_bank.py`),
JSON, Node (`npm run build`, `node --test`).

**Spec:** `docs/superpowers/specs/2026-10-16-dossier-provinces-design.md` (общие правила — спецификации
досье «Деньги», «Мифы и Космос», «Праздники», «Династии» в `docs/superpowers/specs/`).

## Global Constraints

- Вопрос по-русски, варианты по-китайски; правки готовых записей — только через `data/review/editorial.json` с `reason`.
- id вопросов (`provinces-qNN`), строк и исходных вариантов олимпиады не меняются после принятия; текст варианта меняется только через `editorial.json` (`options`).
- У строки — не меньше двух официальных или академических источников с дословной цитатой; Википедия — не источник.
- `country` и `kind` — без `ru`; доля вопросов — около 70 % Китай, 30 % Россия.
- id строк с префиксом таблицы: `prov-`, `city-`, `city-ru-`.
- Колонки названия провинции: `name` (四川), `full` (四川省); вопрос берёт набор из колонки своей формы.
- Мосты внутри досье: `provinces.capital` → `ref` на `cities`, `cities.region` китайского города → `ref` на `provinces`.
- `ru` — названия от шести букв или из двух слов («провинция Хэбэй», «Нижний Новгород»).
- Каждый запуск агентов — с согласия автора (число агентов назначает автор); модели: сборщики — Sonnet, сверщики, писатели, проверяющие, ревью — Opus, механика — Haiku.
- В HTTP-запросах агентов — никаких личных данных, только обезличенный User-Agent.
- Каждое заметное изменение — запись в `CHANGELOG.md` в том же коммите.
- Слияние: вопрос автору о ревью; master — `git push origin feat/dossier-provinces:master` и `git fetch origin master:master`, основную копию репозитория не трогать; если master ушёл вперёд — сначала `sync_with_base_branch` или merge `origin/master`.

## Review Focus

Автоматика сборки этого не ловит; каждую строку проверяет проверяющий (Task 5) и ревью перед слиянием:

1. Второй верный ответ в общем наборе встраивания: превосходные степени (газ — 新疆, площадь — 台湾省, порт — 宁波, Байкал — 乌兰乌德, граница Европы и Азии — другие уральские города). Строку, которая даёт второй ответ, не заводить; если она нужна другому вопросу — вопрос не встраивать.
2. Подсказка формой: краткое название среди полных, сокращение из двух иероглифов среди одиночных, прозвище с 都 среди прозвищ с 城, российский город с «·» или 畔.
3. Утечки через китайские тексты встроенных вопросов (太原 в 2018-19-mun-55, 江西 в 2017-18-mun-10, 北京 и 天津 в разных текстах): сокращения 京, 津 не спрашивать; ответ, названный в чужом тексте, — только через мост `ref`.
4. Правка написания российского города в `editorial.json` меняет текст варианта у нескольких записей: подписи `glosses.json` и копии `zh` в подписях остановят сборку — править вместе.
5. Российский вопрос, где ответ находится отсевом (единственная республика среди областей, единственный город на Волге), — урок «Мифов» и «Праздников».
6. Тайвань: только география и культура, в формулировках олимпиадных ключей, без вопросов о статусе и центре.
