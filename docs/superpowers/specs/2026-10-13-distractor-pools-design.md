# Один вопрос с меняющимися неверными вариантами

## Цель

Олимпиада задаёт один и тот же вопрос из года в год, меняя неверные варианты. Сейчас
такие записи лежат в банке по отдельности и связаны группой «один факт»
(`data/review/fact-groups.json`): в один раунд две записи группы не попадают, но
режим «Новые» считает их разными вопросами. Ученик отвечает на одну запись, а через
несколько раундов получает тот же вопрос с другими вариантами. Это и была жалоба:
«либо у нас есть одинаковые вопросы, либо фильтр по новым не всегда срабатывает».

Решение: записи одной группы с одинаковым ответом становятся одним вопросом. Его
неверные варианты складываются в общий набор, и при каждом показе раунд берёт
правильный вариант и три случайных неверных. Ученик видит вопрос один раз, а
неверные варианты продолжают учить: в подписях есть сведения о каждом.

Решение автора: важнее получить знания, чем повторить олимпиадное задание в
точности. Сочетание вариантов на экране может не совпадать ни с одним годом, но
каждый вариант взят из олимпиады, а появления (год, этап, номер) у записи сохраняются.

## Границы

- Пилот — четыре группы (раздел «Пилот»). Остальные группы и кандидаты из
  `data/review/similar-questions.md` — следующими порциями, после того как автор
  посмотрит пилот у ученика.
- Объединяются только записи с одинаковым правильным ответом. Записи с разными
  ответами на один вопрос (романы: 金瓶梅 / 骆驼祥子; метро: Воронеж / Пермь)
  остаются группами `fact-groups.json`: в общем наборе один ответ мог бы оказаться
  неверным вариантом рядом с другим.
- Как режиму «Новые» вести себя с группами, которые остаются в `fact-groups.json`, —
  отдельное решение автора, в эту работу не входит.
- Переработка парных вопросов в новые вопросы по теме — работа над досье, не здесь.

## Формат данных

Объединение — это склейка (`data/review/merges.json`) с пометкой
`"distractors": "pool"`:

```json
"2017-18-shk-4": {
  "absorbs": ["2018-19-mun-50", "2017-18-zak-2", "2024-25-mun-35"],
  "distractors": "pool",
  "reason": "«Искусство войны»: один вопрос, олимпиада меняла неверные варианты"
}
```

Другое значение поля `distractors` — ошибка сборки. Без поля склейка работает как
сейчас и требует одинаковых вариантов.

## Сборка

Слои идут в прежнем порядке: правки `editorial.json` → склейки `merges.json` →
группы `fact-groups.json` → подписи `glosses.json`. Объединение — часть склеек.

Что делает объединение (всё, кроме вариантов, — как у обычной склейки, тем же кодом):

- Остаётся запись с более ранним появлением. Её формулировка, тема и пояснение
  сохраняются. Появления и источники влитых записей переходят в неё, в `mergedIds`
  записываются влитые id. Прогресс учеников переносит существующий
  `migrateProgress` (`src/quiz.mjs`).
- Варианты: o1–o4 оставшейся записи, затем неверные варианты влитых записей в
  порядке `absorbs`, которых ещё нет (сравнение по `normalize_text`). Новые
  получают id `o5`, `o6`… Правильный ответ — вариант оставшейся записи.
- Официальный ключ (`officialKey`) появлений влитой записи пересчитывается в id
  варианта оставшейся записи по тексту, как сейчас.

Сборка останавливается, если у объединения:

1. правильные ответы записей не совпадают по тексту. Разную запись одного ответа
   (`2001` / `2001 年`) выравнивают правкой `editorial.json`, она идёт раньше
   склейки;
2. не прибавилось ни одного нового неверного варианта. Тогда это обычная склейка,
   и ошибка подсказывает убрать пометку;
3. пояснение оставшейся записи содержит текст какого-нибудь неверного варианта.
   На экране этого варианта может не оказаться, поэтому пояснение говорит только о
   правильном ответе, а сведения о неверных вариантах живут в подписях;
4. варианты-годы записаны по-разному: одни с `年`, другие без (вариант-год — число
   из 3–4 цифр, с `年` или без).

Остальное ловят существующие проверки:

- группа `fact-groups.json` со влитым id → «записи нет в банке». Объединённая
  группа удаляется из `fact-groups.json`;
- подпись `glosses.json` к влитой записи → «записи нет в банке». Подписи влитых
  записей переносятся вручную на id вариантов оставшейся записи; копия текста
  варианта в подписи сверяется, как сейчас.

## Интерфейс

Раунд (`labelledOptions` в `src/quiz.mjs`):

- у записи больше четырёх вариантов → правильный и три случайных неверных, затем
  перемешивание; буквы A–D — по видимому порядку, как сейчас;
- у записи четыре варианта → поведение не меняется;
- варианты выбираются при каждом показе заново, в том числе при повторе ошибки в
  раунде;
- подписи появляются только под показанными неверными вариантами — нынешний код
  берёт их по кнопкам на экране, менять его не нужно;
- проверка ответа, счёт, клавиши 1–4, повтор ошибки не меняются.

База вопросов (`src/quiz.ui.js`, `src/template.html`):

- в карточке видны все варианты, рядом метка «варианты меняются»;
- под «Показать ответ» в «Другие варианты» — подписи ко всем неверным вариантам;
- поиск уже идёт по всем вариантам.

Правки в `src/` маленькие. Если сессия редизайна сольётся раньше, они переносятся
поверх неё.

## Тесты

Тесты пишутся до кода.

Python (`test/test_merges.py`):

- объединение складывает варианты в порядке `absorbs`, новые id `o5`…, без
  повторов по тексту; правильный ответ — вариант оставшейся записи;
- официальный ключ влитой записи указывает на вариант с тем же текстом;
- отклоняются: разные ответы; ни одного нового варианта; пояснение с текстом
  неверного варианта; годы с `年` и без; неизвестное значение `distractors`;
- склейка без пометки с разными вариантами по-прежнему отклоняется;
- на реальных данных: каждое объединение дошло до банка (варианты оставшейся
  записи — объединение вариантов всех записей), влитых id в банке нет.

Node (`test/quiz.test.mjs`):

- `labelledOptions` у записи с 7 вариантами: ровно 4, правильный всегда среди
  них, буквы A–D, за много показов встречается каждый неверный;
- у записи с 4 вариантами результат прежний (существующие тесты).

Браузер (`test/ui.test.mjs`):

- у объединённого вопроса в раунде 4 варианта, правильный среди них;
- в базе у него все варианты и метка «варианты меняются»;
- перенос прогресса влитой записи уже покрыт существующим тестом.

Проверки проекта: `python3 -m unittest discover -s test -t .` и
`node --test test/*.test.mjs`.
