# Тренажёр по лингвострановедению — спецификация

Дата: 2026-09-18

## Цель

Свести разрозненные базы вопросов по лингвострановедению ВсОШ по китайскому языку в один
канонический банк, у которого каждый вопрос имеет проверенный ответ, пояснение и ссылку на
источник, и собирать из этого банка один самодостаточный HTML-файл для подготовки учеников.

Проект живёт в `~/Documents/Projects/lingvostranovedenie-trainer` как git-репозиторий, в одном
ряду с остальными основными проектами. Черновая папка `~/Documents/Codex/2026-09-17/html`
остаётся нетронутой: из неё копируются исходники, её судьба решается отдельно.

## Исходные материалы

Все первоисточники копируются в `sources/` репозитория. Сборка читает только их и никогда не
обращается к Яндекс.Диску: иначе она перестанет воспроизводиться при переезде или отключении
синхронизации папки.

| Файл | Содержание | Роль при слиянии |
|---|---|---|
| `Банк вопросов — лингвострановедение (423, с ответами).docx` | 423 вопроса, 2015-16 … 2025-26, все пять этапов, русский перевод вопросов, официальные ключи | основа банка |
| `Вопросы по категориям (310 шт).docx` | 310 вопросов, разложенных по 7 смысловым категориям | источник рубрикации и ~8 недостающих вопросов |
| `Лингвострановедение ВсОШ.docx` | сводный сборник 2015/16–2025/26 на китайском, ключи по этапам в конце | сверка формулировок и ключей |
| `Лингвострановедение 2022-23 — Школьный / Муниципальный / Региональный / Заключительный.pdf`, `2023-24.pdf`, `2024-25.pdf` | оригинальные бланки олимпиады, текст извлекается без OCR | первоисточник: старший авторитет по формулировкам и ключам |

Замеренное пересечение баз: из 310 вопросов второй базы 302 уже есть в банке 423, из ~309
вопросов сводного сборника — 295. Банк 423 является практически надмножеством; остальные базы
дают рубрикацию, полтора десятка недостающих вопросов и независимую сверку.

## Объём работ

В объём входит:

- перенос проекта в `~/Documents/Projects/lingvostranovedenie-trainer` с git-репозиторием,
  `README.md`, `SPEC.md` и `CLAUDE.md`;
- воспроизводимый конвейер: импорт DOCX и PDF → слияние с дедупликацией → сборка одного HTML;
- канонический банк `data/bank.json` с единой рубрикацией из семи категорий;
- проверка ответа и пояснение для каждого вопроса, с источником и датой проверки;
- интерфейс: стартовый экран, раунд, база вопросов — с показом пояснений, ссылок и статуса
  проверки;
- тесты на схему банка, дедупликацию, логику раунда, сборку и воспроизводимость импорта.

В объём не входит: аккаунты, серверная часть, синхронизация прогресса между устройствами,
интервальные повторения, другие разделы олимпиады кроме лингвострановедения.

## Структура репозитория

```
lingvostranovedenie-trainer/
├── README.md, SPEC.md, CLAUDE.md
├── sources/                     # копии первоисточников: 3 DOCX + 5 PDF
├── data/
│   ├── bank.json                # канонический банк — единственный источник правды
│   ├── taxonomy.json            # семь категорий и правила отнесения
│   ├── raw/                     # промежуточный результат импорта, по файлу на источник
│   └── review/                  # отчёты слияния, рубрикации и волн проверки
├── scripts/
│   ├── import_docx.py           # разбор DOCX через zipfile + XML, без внешних зависимостей
│   ├── import_pdf.py            # разбор PDF через pdftotext
│   ├── merge_bank.py            # слияние, дедупликация, рубрикация
│   └── build_html.py            # сборка одного самодостаточного HTML
├── src/
│   ├── template.html, quiz.mjs, quiz.css
├── test/                        # node --test
└── dist/lingvostranovedenie-trainer.html
```

Поток данных: `sources/` → импортёры → промежуточные JSON в `data/raw/` → `merge_bank.py` →
`data/bank.json` → `build_html.py` → `dist/lingvostranovedenie-trainer.html`.

Импорт DOCX идёт через `zipfile` и разбор `word/document.xml` штатной библиотекой XML: на машине
нет `python-docx`, а лишняя зависимость ради чтения трёх файлов не нужна. Импорт PDF — через
`pdftotext`, который в системе есть и извлекает текст этих бланков без OCR.

## Модель данных

```js
{
  id: '2015-16-shk-56',                            // год, этап и номер первого появления
  topic: 'География и административное устройство', // одна из семи категорий
  topicSource: 'categories-310' | 'assigned',       // откуда взялась метка темы
  questionRu: 'Какой город является крупнейшим портовым городом Китая?',
  questionZh: '中国最大的港口城市是哪一个？',
  options: [
    { id: 'o1', zh: '广州' },
    { id: 'o2', zh: '上海' },
    { id: 'o3', zh: '北京' },
    { id: 'o4', zh: '西安' }
  ],
  occurrences: [
    { year: '2015-16', stage: 'школьный', grades: '9-11', number: 56, officialKey: 'o2',
      sourceFile: 'Банк вопросов — лингвострановедение (423, с ответами).docx' }
  ],
  answer: { optionId: 'o2', state: 'verified' },   // unverified | verified | conflict | needs-review
  explanation: { ru: 'Почему верен этот вариант и чем ошибочны остальные.' },
  evidence: [ { title: 'Шанхайский порт — статистика контейнерооборота',
                url: 'https://www.portshanghai.com.cn/', checkedAt: '2026-09-18' } ],
  wave: 1,                                          // номер волны проверки, 0 до проверки
  parseWarnings: []
}
```

`id` складывается из года, латинского кода этапа и номера самого раннего появления вопроса.
Тема в `id` не участвует намеренно: рубрикация может измениться, а идентификатор, по которому
хранится прогресс ученика, обязан пережить такое изменение.

Метки A–D нигде не хранятся. Правильность связана со стабильным `optionId`, а буквы рисуются по
видимому порядку вариантов в момент показа. Это устраняет дефект, при котором перемешивание
вариантов рассыпало соответствие буквы и ответа.

`occurrences` — список всех появлений вопроса в материалах олимпиады. Дубликаты не удаляются, а
склеиваются: один и тот же вопрос кочует из этапа в этап, и его история — полезные данные, по
которым работает фильтр по году и этапу.

### Состояния ответа

| Состояние | Когда присваивается | Попадает в раунд |
|---|---|---|
| `unverified` | ответ известен из ключа, но проверка по интернету ещё не проводилась | да, с пометкой в разборе |
| `verified` | ответ подтверждён источником, есть пояснение и ссылка | да |
| `conflict` | ключи разных появлений расходятся между собой, либо проверка разошлась с официальным ключом | нет, до решения владельца проекта |
| `needs-review` | ответа нет ни в ключах, ни по результатам проверки | нет |

## Рубрикация

Канонической становится рубрикация из базы «Вопросы по категориям (310 шт)» — семь категорий:

1. География и административное устройство
2. Россия и межкультурный блок
3. Литература, язык, искусство и философия
4. История и государство
5. Общество: население, этносы и религии
6. Экономика, образование, наука и спорт
7. Культура, традиции и праздники

Причина выбора: в рубрикации банка 423 нет темы про Россию, хотя вопросов про российские реалии
в олимпиаде много, а роль отстойника играет тема «Разное» с 50 вопросами. В рубрикации «310»
«Разного» нет, а межкультурный блок выделен в отдельную категорию из 54 вопросов.

Перенос меток: ~302 вопроса получают тему автоматически из совпадения с базой «310». Остальные
~130 размечаю я при слиянии, и все такие метки — с `topicSource: 'assigned'` — целиком попадают в
отчёт `data/review/taxonomy.md` на вашу сверку. Тема «Разное» в
итоговом банке отсутствует; вопрос, который не удалось отнести уверенно, получает тему по
преобладающему признаку и помечается в отчёте как спорный.

## Правила слияния

1. Ключ дедупликации — нормализованный набор вариантов вместе с нормализованным текстом вопроса.
   Нормализация: NFKC, удаление пробелов и переводов строк, снятие буквенной метки варианта,
   снятие концевой пунктуации.
2. Совпавшие записи склеиваются в одну; их `occurrences` объединяются и сортируются по году и
   этапу.
3. Расхождение официальных ключей между появлениями одного вопроса не разрешается автоматически:
   запись получает состояние `conflict` и попадает в отчёт.
4. Формулировка вопроса и текст вариантов берутся из PDF-первоисточника, если он есть для этого
   года и этапа; иначе из DOCX. Русский перевод берётся из банка 423, а при его отсутствии — из
   базы «310». Вопрос, которого нет ни в одной из двух русских баз, перевожу при слиянии; такие
   переводы перечислены в отчёте о слиянии отдельным списком на вашу вычитку.
5. Мусор из исходников — колонтитулы, «Максимум за задание», номера страниц, приклеившиеся к
   вариантам, — вычищается при импорте; каждый случай вычистки пишется в `parseWarnings`.
6. Слияние детерминировано: повторный запуск на тех же `sources/` даёт побайтово тот же
   `data/bank.json`.
7. Отчёт `data/review/merge.md` показывает: сколько записей на входе от каждого источника,
   сколько склеено, сколько уникальных на выходе, список нераспознанных фрагментов.

## Протокол проверки ответов

Все 118 записей, помеченных в старом банке как `web-verified`, при импорте понижаются до
`unverified`. Основание: на 118 записей приходится всего четыре уникальные ссылки, и они не
относятся к своим вопросам — например, вопрос о годах Русско-японской войны сослан на
Конституцию КНР. Официальные ключи из DOCX и PDF при этом сохраняются полностью.

Проверяется каждый вопрос, включая те, у которых официальный ключ есть. Для каждого:

1. Найти источник, прямо отвечающий на этот вопрос. Приоритет: официальные сайты (gov.cn, ВСНП,
   ЮНЕСКО, Росстат, сайты музеев, вузов и оргкомитета ВсОШ) → энциклопедические справочники →
   прочие. Ссылка сохраняется вместе с датой проверки.
2. Написать пояснение на русском в 1–3 предложения: почему верен выбранный вариант и чем
   ошибочны остальные. Китайские реалии в пояснении даются иероглификой, поскольку варианты
   ответа китайские.
3. Вопросы, зависящие от времени, оцениваются по состоянию на год своей олимпиады, который уже
   хранится в `occurrences`. Ответ 2015 года не переписывается по сегодняшним данным.
4. Если проверка расходится с официальным ключом, ответ не переписывается молча: запись получает
   `conflict`, обе версии и обоснование попадают в отчёт волны.
5. Если источника найти не удалось, запись получает `needs-review`. Ответ не выдумывается.

### Волны

Проверка идёт волнами примерно по 50 вопросов. Порядок: волна 1 — вопросы без ключа и вопросы с
расхождением ключей; далее по темам, начиная с крупнейшей.

Каждая волна заканчивается коммитом, пересборкой `dist/` и отчётом `data/review/wave-N.md`, в
котором отдельным разделом перечислены расхождения с официальными ключами. Работа прерываема:
номер волны хранится в каждой записи, и следующий заход продолжает с того места, где остановился
предыдущий.

## Интерфейс

Один самодостаточный HTML-файл, работающий без сети и без сборки. Три экрана.

**Старт.** Выбор тем (несколько или все), размер раунда 5 / 10 / 20 / 50 / все подходящие,
галочка «только непройденные» и галочка «только проверенные», выключенная по умолчанию. Счётчик
показывает, сколько вопросов подходит под текущие фильтры и сколько из всего банка уже проверено. Если под фильтры не подходит ни один вопрос, кнопка
старта выключена и рядом сказано почему.

**Раунд.** Вопрос по-русски, варианты по-китайски, тема, год и этап, прогресс и счёт. Варианты
перемешиваются, метки A–D присваиваются по видимому порядку, правильность считается по
`optionId`. После ответа — разбор: верный вариант, пояснение, ссылки на источники, дата проверки.
Непроверенный вопрос в разборе прямо помечен как непроверенный.

**База.** Все вопросы с поиском по русскому тексту и фильтрами по теме, году, этапу, статусу
проверки и пройденности. Карточка раскрывается в подробности: китайский оригинал вопроса, все
появления в материалах олимпиады, ответ, пояснение и ссылки.

Прогресс (попытки, верные ответы, пройденность, последний результат) хранится в `localStorage`
под версионированным ключом. При несовпадении версии сбрасывается только прогресс; банк вопросов
не трогается.

## Тесты

`node --test` в `test/`:

- схема банка: уникальные `id`, ровно четыре варианта, `answer.optionId` указывает на
  существующий вариант, тема входит в `taxonomy.json`, у `verified` есть пояснение и хотя бы одна
  ссылка;
- дедупликация: записи с одинаковым нормализованным набором вариантов склеены, `occurrences`
  отсортированы, расхождение ключей даёт `conflict`;
- логика раунда: метки A–D идут по видимому порядку при любом перемешивании, правильность
  считается по стабильному `optionId`, внутри раунда вопрос не повторяется, размер раунда не
  превышает подходящее множество, фильтры меняют счётчик;
- сборка: в `dist/` ровно один файл, в нём нет внешних ссылок на скрипты и стили, банк встроен;
- воспроизводимость: повторный прогон импорта и слияния на `sources/` даёт тот же `data/bank.json`.

## Критерии готовности

- `data/bank.json` содержит все уникальные вопросы из трёх DOCX и пяти PDF, без потерь и без
  дублей; отчёт о слиянии сходится по числам.
- Ни один вопрос не имеет темы «Разное»; все темы входят в список из семи категорий.
- Каждый вопрос со статусом `verified` имеет пояснение и хотя бы одну ссылку, относящуюся именно
  к нему.
- Расхождения с официальными ключами не спрятаны: они перечислены в отчётах волн и видны в базе
  как `conflict`.
- Тренажёр открывается двойным щелчком по файлу, работает без сети, прогресс переживает
  перезагрузку страницы.
- Все тесты проходят.

## Порядок работ

1. Репозиторий, перенос исходников, копирование первоисточников в `sources/`, первый коммит.
2. Импортёры DOCX и PDF, промежуточные JSON, отчёт о разборе.
3. Слияние с дедупликацией и рубрикацией → `data/bank.json`, отчёты `merge.md` и `taxonomy.md`.
4. Сборка HTML и тесты — рабочий тренажёр на руках.
5. Волны проверки ответов с пояснениями, по волне за заход.
