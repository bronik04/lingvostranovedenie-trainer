# Подписи к неверным вариантам

## Цель

После ответа ученик узнаёт не только, почему верен правильный вариант, но и что
такое остальные три. В олимпиаде неверные варианты одного задания часто
оказываются верными ответами других, поэтому короткая подпись к каждому из них
превращает один вопрос в четыре факта.

Пример — вопрос о первой единой централизованной династии, ответ 秦朝:

- 汉朝 — «Династия Хань, 206 г. до н. э. — 220 г.»
- 明朝 — «Династия Мин, 1368–1644»
- 夏朝 — «Династия Ся, ок. 2070–1600 гг. до н. э.»

## Границы

- Пилот — тема «История и государство»: 74 вопроса (69 олимпиадных и
  5 дополнений), около 220 неверных вариантов. Остальные темы — после пилота и
  отдельного решения автора о том, как их проверять.
- Подпись есть только у неверных вариантов. Правильный вариант объясняет
  пояснение.
- Подпись необязательна. Если о варианте нечего сказать правдиво и полезно
  («3 个», выдуманное название вроде 四星红旗), подписи нет. Годы подписываются,
  если с годом связано событие, которое стоит знать («1911 — Учанское восстание,
  начало Синьхайской революции»).
- В проект попадают только подписи, принятые автором на странице проверки.
  Код сливается раньше, с пустым слоем: без данных ничего не меняется.

## Какой бывает подпись

Одна строка по-русски, не длиннее 90 символов: русское название и один
опознавательный факт — годы, роль, место. Без оценки «почему не подходит» и
без повторения самого варианта по-китайски (он и так стоит рядом). Китайские
иероглифы в подписи допустимы только как часть названия, например 《史记》.

## Формат данных

Новый файл `data/review/glosses.json`, ключ — итоговый id записи банка:

```json
{
  "2015-16-zak-4": {
    "reviewedAt": "2026-09-25",
    "options": {
      "o2": {
        "zh": "汉朝",
        "ru": "Династия Хань, 206 г. до н. э. — 220 г.",
        "source": {"title": "汉朝 — 中国大百科全书", "url": "https://..."}
      }
    }
  }
}
```

`zh` — копия текста варианта, к которому писалась подпись. Если вариант потом
исправят через `editorial.json`, подпись перестанет с ним совпадать, и сборка
остановится: подпись нужно перепроверить, а не показывать к другому тексту.
`source` хранится для аудита и в интерфейсе не показывается.

## Сборка и проверки

`scripts/glosses.py` по образцу `editorial.py`: `load_glosses`,
`validate_glosses`, `apply_glosses`. `merge_bank.py` применяет подписи
последним слоем, после правок, и кладёт текст в вариант: `options[i].gloss`.

Сборка останавливается, если:

- записи или варианта с таким id нет;
- подпись висит на правильном варианте;
- `zh` не совпадает с текущим текстом варианта;
- в `ru` нет кириллицы, она длиннее 90 символов или содержит «— —» и двойные
  пробелы (латиницу не запрещаем: римские цифры веков — тоже латиница);
- у подписи нет источника с HTTP(S)-ссылкой и названием;
- нет `reviewedAt`.

Тест на реальных данных проверяет, что каждая подпись из файла дошла до
`data/bank.json`.

## Интерфейс

- Раунд: после ответа под китайским текстом каждого неверного варианта,
  у которого есть подпись, появляется серая строка. Кнопка варианта при этом
  остаётся той же — с буквой и пометками «✓ Верно» / «✕ Ваш ответ».
- База: в блоке «Показать ответ» под пояснением — список «Другие варианты»
  в виде «汉朝 — Династия Хань, …».
- На телефоне строка переносится внутри кнопки, горизонтальной прокрутки нет.
- Текст подписи выводится через `textContent` / `escapeHtml`, как остальные
  данные банка.

## Процесс пилота

1. Черновик: для каждого из 74 вопросов подписи к неверным вариантам, у каждой —
   источник (энциклопедия, официальный сайт) и короткая цитата, подтверждающая
   факт. Варианты без подписи помечаются причиной пропуска.
2. Независимая сверка: отдельный агент открывает источники и проверяет каждую
   подпись. Спорные исправляются или снимаются до показа автору.
3. Страница проверки (`claude.ai/artifact/WASjGdZGgNfjLARdoEBPKt`) получает
   вкладку «Подписи к вариантам»: карточка на вопрос — вопрос, варианты с
   отмеченным ответом, подписи под неверными с источниками и цитатами;
   решения «Принять / Нужна правка / Отклонить» и комментарий на весь вопрос.
   Данные — в `items` (вид `gloss`), решения — в `decisions` (`gloss-<id>`).
4. Принятые и исправленные по комментарию подписи записываются в
   `data/review/glosses.json`, банк пересобирается, тесты, запись в
   `CHANGELOG.md`, ревью ветки, слияние.
